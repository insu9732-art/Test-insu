# script-to-motion

대본이나 주제만 건네면 **목소리 내레이션이 입혀진 모션그래픽 영상**을 만들어 주는 에이전트 스킬입니다.
글을 쓰고, 목소리를 입히고, 장면을 디자인하고, 움직임을 말에 맞추는 일을 에이전트가 맡습니다.
여러분은 결과를 보고 듣고, 고칠 점을 평소 말하듯 알려 주면 됩니다.

---

## 3단계로 시작하기

1. **설치** — 이 폴더를 에이전트가 스킬을 읽는 곳에 둡니다([설치](#설치) 참고).
2. **부탁** — "이 대본으로 유튜브 영상 만들어줘"처럼 말합니다. 대본이 없으면 주제만 말해도 됩니다.
   목소리 내레이션을 넣으려면 **Fish Audio API 키와 음성 ID**를 함께 주세요([내레이션](#내레이션은-fish-audio로) 참고).
3. **영상 파일로** — 완성된 폴더에서 `python3 render.py`를 실행하면 `movie_<날짜-시각>_<해상도>.mp4`(예: `movie_20261106-213045_1080p.mp4`)가 만들어집니다(끊김 없음, 480p·720p·1080p·4K).
   화면 녹화로 만들어도 됩니다: `index.html`을 Chrome으로 열면 로딩바가 찬 뒤 곧바로 재생됩니다 — `F`로 전체화면, 녹화를 켠 뒤 `R`(처음부터)([결과물과 영상 파일](#결과물과-영상-파일) 참고).

## 무엇을 만들 수 있나요

| 종류 | 예 |
|---|---|
| 유튜브 설명·지식 영상 | 과학 상식, 역사 이야기, 경제 개념, 책 요약, 다큐 인트로 |
| 쇼츠·릴스·틱톡 | 짧은 팁, 놀라운 사실 하나, 오늘의 단어, 제품 한 장면 |
| 홍보·광고 | 가게·브랜드 소개, 신제품·앱 출시, 이벤트 공지, 채용 소개 |
| 교육·강의 | 수업 오프닝, 개념 정리, 공식·과정 설명, 퀴즈 |
| 회사·발표 | 발표 시작 영상, 실적·데이터 브리핑, 회사 소개, 행사 오프닝 |
| 개인 프로젝트 | 축하 영상, 여행 기록 요약, 포트폴리오 소개, 채널 인트로 |
| 제품 시연·AI 도구 리뷰 | 내 화면 녹화와 생성 결과를 넣은 리뷰, 계획한 콘티 vs 실제 결과 비교, 협찬 캠페인 영상 |
| 긴 영상 (여러 장) | 장(챕터)마다 질문을 하나씩 던지고 답하는 구성, 장 표지와 시그니처 전환 |

화면에서는 이런 것들이 움직입니다.

- **말과 딱 맞물리는 움직임** — 숫자는 말하는 순간 올라가고, 핵심 단어는 그 단어를 말할 때 나타납니다.
- **감각적인 타이포그래피** — 글자가 유리처럼 깨지고, 녹아내리고, 물결처럼 출렁이고, 젤리처럼 튀고, 한글 자모가
  날아와 글자가 되고, 먼지처럼 흩어지고, 네온처럼 켜지고, 두께를 가진 입체가 됩니다. 장면에 맞는 새 효과도 만들어 냅니다.
- **그림과 연출** — 사람, 동물, 탈것, 지도 같은 일러스트, 카메라 이동, 빛과 입자 효과, 필요하면 3D까지.
- **데이터** — 그래프가 그려지고, 숫자가 굴러가며 올라가고, 비교가 한눈에 보이게.
- **원하는 목소리** — 고른 Fish Audio 목소리(내 목소리 클론도 가능)로 내레이션을 만들고, 그 실제 길이에 맞춰 화면을 짭니다.
  내레이션 없이 화면만으로 된 영상도 만들 수 있습니다.
- **원하는 비율** — 가로 16:9, 세로 9:16(쇼츠·릴스·틱톡), 인스타 피드 4:5, 정사각 1:1, 와이드 21:9.
  비율마다 화면을 새로 배치하고, 세로 영상은 앱의 제목·버튼이 덮는 자리를 비워 둡니다.
- **내 녹화 화면과 생성 영상** — 시연 녹화는 확대하지 않고 페이지 전체를 보여 주면서, 설명할 곳만 남기고 나머지를
  어둡게 한 뒤 손으로 붙인 듯한 설명 카드를 답니다. 생성 결과는 자르지 않고 끝까지 틀고, 계획과 나란히 비교합니다.
  개인 정보는 적당한 블러로 가립니다.
- **말한 그 순간에** — 에이전트가 녹음을 소리 수치로 읽고 단어가 들리는 시각을 직접 정해, 숫자와 강조가 그 단어에 정확히 닿게 합니다
  (단어에 꼭 맞아야 하는 곳만; 코드는 단어나 쉼의 위치를 판정하지 않습니다).
- **빈 소리 없이** — 내레이션과 영상 소리를 합친 소리를 50ms마다 잰 수치로 에이전트가 직접 읽고, 0.4초 이상 조용한
  구간을 찾아 줄입니다. 문장 사이는 간격을 줄이고, 한 녹음 안의 긴 쉼은 그 부분만 잘라 냅니다. 통째로 보여 주는
  생성 영상 속 쉼과, 끝에 마지막 화면이 머무는 구간은 그대로 둡니다.
- **끊김 없는 MP4** — `render.py`가 장면을 한 프레임씩 그려 찍기 때문에, 컴퓨터가 느려도 프레임이 빠지지 않습니다.
  자막과 내레이션, 영상 클립의 소리까지 함께 넣고, 맥에서는 그래픽 칩과 하드웨어 압축으로 빠르게 굽습니다.

## 내레이션은 Fish Audio로

영상의 목소리 내레이션은 [Fish Audio](https://fish.audio)로 만듭니다.

- **내레이션을 넣고 싶다면, 요청할 때 Fish Audio API 키와 음성 ID를 함께 주세요.** 둘 다 있어야 만들 수 있습니다.
  스킬에는 기본 목소리가 없고, 다른 음성 합성 서비스도 쓰지 않습니다.
  - **음성 ID** — fish.audio에서 고른 목소리 모델(내 목소리 클론도 가능)의 ID.
  - **API 키** — fish.audio 계정의 API 키.
- **둘 중 하나라도 없으면 내레이션 없는 영상**으로 만듭니다. 화면의 글자와 움직임으로 내용을 전하고, 읽을 수 있는
  속도로 타이밍을 맞춥니다. 나중에 키와 ID를 주면 목소리를 입힐 수 있고, 장면은 새 길이에 맞춰 따라옵니다.

전달하는 방법

```
아래 대본으로 영상 만들어줘. Fish Audio 음성 ID는 0a1b2c…, API 키는 .env에 넣어 뒀어.
```

- 음성 ID는 요청에 그대로 적으면 됩니다. `.env` 파일에 `FISH_VOICE=...`로 적어 둬도 됩니다.
- API 키는 **스킬 폴더의 `.env`** 파일에 `FISH_API_KEY=...` 한 줄로 넣어 두는 방법을 권합니다. 이 파일은 git에
  올라가지 않습니다. 영상 폴더나 그 상위 폴더의 `.env`도 읽습니다.
  요청에 직접 적어도 동작하지만, 그러면 키가 대화 기록에 남습니다. 요청으로 받은 키는 에이전트가 스킬 폴더의 `.env`에만
  저장하고, 다른 파일·출력·메모리에는 적지 않습니다.
- Fish Audio 사용 요금은 그 계정에 청구됩니다.

## 이렇게 부탁해 보세요

평소 말투면 충분합니다. 스킬 이름(`script-to-motion`)을 함께 말해도 되고, 그냥 "영상 만들어줘"라고 해도 됩니다.

### 대본이 있을 때

```
아래 대본으로 유튜브 설명 영상 만들어줘. 차분하고 깔끔한 느낌으로.

(대본 붙여넣기)
```
```
이 강의 오프닝 원고로 영상 만들어줘. 대학 신입생 대상이야.
```

대본의 문장은 바꾸지 않습니다. 숫자나 영어 단어가 자연스럽게 읽히도록 발음만 다듬습니다.

### 주제만 있을 때

```
"세상에서 제일 깊은 바다는 어디일까?"를 주제로 흥미롭게 기획해서 영상으로 만들어줘. 자료조사도 충분히 해줘.
```
```
초등학생도 이해할 수 있게 "블랙홀은 왜 검을까?" 영상 만들어줘.
```
```
"커피는 몸에 좋을까 나쁠까"를 근거 중심으로, 한쪽으로 치우치지 않게 정리한 영상.
```

대본이 없으면 주제 한두 문장만으로 충분합니다. 에이전트가 웹에서 자료를 찾아 출처를 확인하고(`research.md`),
기획(대상, 핵심 메시지, 구성)을 세운 뒤 대본을 써서 영상까지 완성합니다. 길이는 미리 정하지 않습니다. 시청자가 알아야
할 내용을 빠짐없이, 제대로 전하는 데 필요한 만큼이 영상의 길이가 됩니다.

### 기획서가 있을 때

```
첨부한 기획서대로 신제품 소개 영상 만들어줘.
```

기획서에서 정한 것은 그대로 지킵니다. 대상, 꼭 넣을 문장(글자 그대로), 꼭 보여 줄 것, 장면 지시와 순서, 금지 사항이
여기에 해당합니다. 기획서에 길이가 적혀 있어도 꼭 해야 할 말을 빼면서까지 맞추지는 않습니다. 내용이 더 필요하면 그대로
담고, 얼마나 길어졌는지와 그 이유를 알려 드립니다. 정하지 않은 부분은 에이전트가 조사해서 채웁니다. 기획서 항목이 어디서 지켜졌는지는
`storyboard.md`의 표로 확인할 수 있습니다.

### 글·기사·문서를 영상으로

```
이 블로그 글을 요약 영상으로 만들어줘.
```
```
첨부한 분기 보고서의 핵심 숫자 다섯 개만 뽑아서 임원 보고용 영상으로 만들어줘. 그래프 위주로.
```
```
이 뉴스 기사를 쇼츠로. 첫 2초 안에 핵심을 보여줘.
```

### 짧은 SNS 영상

```
이 글을 세로 쇼츠로 만들어줘. 빠르고 경쾌하게.
```
```
"하루 10분 스트레칭 3가지" 릴스용으로. 소리 없이 봐도 이해되게 글자를 크게.
```
```
인스타 피드용(4:5) 신메뉴 소개 영상.
```

### 홍보·광고

```
우리 동네 빵집 소개 영상. 따뜻하고 감성적으로, 마지막에 가게 이름과 위치.

(소개 문구 붙여넣기)
```
```
새 앱 출시 영상. 문제 → 해결 → 핵심 기능 3개 → 다운로드 안내 순서로. 브랜드 색은 #3D7BFF.
```
```
행사 오프닝 영상. 무대 스크린이 21:9야. 웅장하게.
```

### 교육·발표·데이터

```
피타고라스 정리를 그림으로 증명하는 영상.
```
```
조선 왕조 500년을 타임라인으로 훑는 영상.
```
```
지난 5년 매출 추이(첨부한 숫자)를 보여주는 발표 오프닝 영상. 마지막에 올해 목표를 크게.
```

### 스타일까지 정하고 싶을 때

```
전체적으로 어두운 남색에 형광 청록 포인트. 글자는 두껍게.
```
```
"기록이 깨졌다"에서 숫자가 진짜 유리처럼 산산조각 났으면 좋겠어.
```
```
제목은 붓글씨 느낌, 본문은 깔끔한 고딕으로.
```
```
영문 타이틀은 글자 폭이 숨 쉬듯 늘었다 줄었다 하게 해줘.
```
```
3D로 지구가 돌다가 한국으로 확대되는 장면을 넣어줘.
```

### 이런 것까지 알려 주면 더 좋아요

- **어디에 올릴지** — 유튜브, 쇼츠, 인스타 피드, 발표 화면 등. 비율과 호흡이 달라집니다.
- **누가 볼지** — 초등학생, 업계 전문가, 고객 등.
- **분위기** — 차분함, 경쾌함, 진지함, 감성적, 웅장함.
- **꼭 들어갈 것** — 가게 이름, 날짜, 연락처, 마지막 문장, 브랜드 색.
- **로고나 사진 파일** — 있으면 파일로 함께 주세요. 그 밖의 그림은 모두 새로 그려서 만듭니다.

## 만드는 과정

에이전트는 대략 이런 순서로 일하고, 단계마다 무엇을 하는지 알려 줍니다.

1. **기획** — 대본이 없으면 먼저 웹에서 자료를 조사합니다. 무엇을 말할지, 어떤 시각 아이디어로 끌고 갈지 정하고,
   장면마다 최대한 풍부하게 표현합니다.
   장면마다 쓸 표현 기법은 [cokacmotion](https://github.com/kstost/cokacmotion) 기법 모음에서 찾습니다.
   기법 하나당 데모 하나씩, 데모 166편이 있습니다. 데모의 노트와 소스를 읽어 원리를 익힌 뒤 이 영상에 맞게 새로 구현합니다.
   데모의 장면, 소재, 색은 가져오지 않습니다.
2. **대본** — 대본이 없으면 쓰고, 있으면 문장 단위로 나눕니다. 대본은 시간 정보 없이 문장만 담은 `script.txt`로도 남습니다. 내레이션은 글이 아니라 말이라서, 문장 끝은 "~니다" 75% ·
   "~요" 25% 정도로 섞고 "자," "사실" "그러니까" 같은 말버릇을 자연스럽게 넣어 실제로 말하는 것처럼 씁니다.
3. **장면** — 소리 없는 임시 음성(읽는 속도로 잡은 길이)에 맞춰 장면과 움직임을 만듭니다. 자막은 처음부터 켜져
   있어 대사를 읽으며 볼 수 있습니다.
4. **확인** — 처음 만들 때는 실제 브라우저로 장면을 캡처해 보면서 겹침, 잘림, 타이밍을 고칩니다. 그 뒤 고치는
   단계에서는 화면은 여러분이 보고, 에이전트는 오류·무음·폰트 검사만 돌려 빠르게 주고받습니다.
   - **고도화** — 결함이 없다고 끝내지 않습니다. 따로 띄운 미술 감독 에이전트가 시트를 보고 장마다 **연출 · 그래픽
     디자인 · 모션**을 1–5점으로 매기고, 고칠 점을 구체적으로 짚습니다. 에이전트는 약한 장면을 처음부터 다시
     설계하고 다시 찍어, 모든 장이 4점 이상이 되거나 세 번을 돌 때까지 반복합니다. 전후 점수와 시트를 함께 알려 드립니다.
5. **전달** — 여기까지는 중간에 묻지 않고 끝까지 완성합니다. 폴더 위치, MP4로 굽는 방법과 재생·녹화 방법,
   대본(`script.txt`)과 조사 출처를 알려 드립니다.
6. **목소리** — 완성된 영상을 보신 뒤 **녹음하라고 하실 때만** Fish Audio(drama-3 모델)로 여러분의 목소리로
   녹음합니다. 목소리와 크레딧은 여러분의 것이라, 에이전트가 스스로 녹음하는 일은 없습니다. 녹음하면 장면이 실제
   음성 길이에 맞춰 자동으로 따라오고, 먼저 들어 볼 문장을 알려 드립니다. 키와 음성 ID는 스킬 폴더의 `.env`(git에
   올라가지 않음)에 두면 자동으로 쓰고, 없으면 내레이션 없는 영상으로 만듭니다.

여러분께 부탁하는 것은 세 가지뿐입니다.

- **Fish Audio API 키와 음성 ID** — 내레이션을 원할 때만 필요합니다. 없으면 내레이션 없는 영상으로 만듭니다.
- **녹음 결정** — 완성된 영상을 보고 녹음할지 정해 주세요.
- **들어 보기** — 에이전트는 소리를 들을 수 없습니다. 발음이 어색한 문장을 알려 주면 그 문장만 다시 녹음합니다.

## 결과물과 영상 파일

결과는 **브라우저에서 재생되는 폴더**입니다(`index.html`과 css·js·소리). 영상 파일은 이 폴더에서 두 가지 방법으로 만듭니다.
`render.py`로 굽거나(끊김 없음), 브라우저 재생을 화면 녹화합니다.
폴더에는 대본 문장만 담은 `script.txt`도 있습니다. 시간 정보 없이 한 줄에 한 문장씩 들어 있습니다.
`generated.json`은 스킬의 도구가 만든 파일(내레이션, 녹음, 클립 프레임, 시트, 영상, 3D 모델)과 각 파일의 해시를 적은 기록입니다.
출처 검사가 이 기록으로 "스킬이 만든 그대로인지"를 확인하니, 손으로 고치지 마세요.

### MP4로 굽기 (`render.py`, 권장)

`render.py`로 MP4를 바로 만들 수 있습니다. 재생하지 않고 프레임마다 그 시각의 장면을 다 그린 뒤
찍으므로, 컴퓨터가 느려도 프레임이 빠지지 않습니다(느리면 시간만 더 걸립니다). 파일 하나로 어디에 두어도 되고, 영상 프로젝트
폴더(index.html이 있는 곳)를 인자로 줍니다. 새 프로젝트 폴더에도 한 부 들어 있어, 그 안에서는 인자 없이 실행해도 됩니다.

- **준비:** Python 3과 ffmpeg(맥은 `brew install ffmpeg`). Debian·Ubuntu는 `python3-venv`도 필요합니다(`sudo apt install python3-venv`.
  없으면 render.py가 이 명령을 알려 주고 멈춥니다). 처음 실행하면 `~/.cache/motion-render-venv`에 가상환경을 만들고
  Playwright와 Chromium을 그 안에 설치한 뒤 시작합니다 — 시스템 파이썬과 프로젝트에는 아무것도 설치하지 않습니다.
- **실행:**
  ```bash
  python3 render.py ~/videos/내영상              # 전체 → ~/videos/내영상/movie_<날짜-시각>_<해상도>.mp4 (60fps, 무대 크기 그대로 — 16:9면 1920×1080)
  python3 render.py ~/videos/내영상/index.html   # index.html을 줘도 같음
  python3 render.py                             # 프로젝트 폴더 안에서 실행할 때는 인자 없이
  python3 render.py ~/videos/내영상 --to 40      # 앞 40초만 (먼저 이것으로 속도·화질 확인)
  python3 render.py ~/videos/내영상 --res 4k     # 4K (무대의 두 배, HEVC)
  python3 render.py ~/videos/내영상 --res 720p   # 720p (무대의 2/3 — 더 빠르고 파일이 작음)
  python3 render.py ~/videos/내영상 --res 480p   # 480p (무대의 4/9 — 미리보기·공유용)
  python3 render.py ~/videos/내영상 --fast --jobs 3   # 더 빠르게: 프레임마다 한 번만 찍기 + 브라우저 3개 동시
  python3 render.py ~/videos/내영상 --quality ultra   # JPEG 100으로 찍어 무손실 압축 (H.264 YUV 4:4:4, 파일이 아주 큼; --png를 더하면 PNG로 찍음)
  python3 render.py ~/videos/내영상 --out ~/Desktop/내영상.mp4   # 다른 곳에 저장(.mp4·.mov — 없는 폴더는 만들고, 시작 전에 확인)
  python3 render.py --help                      # 모든 선택지
  ```
- **맥:** 그래픽 칩으로 그리고(Metal) 하드웨어로 압축합니다(VideoToolbox). 시작 줄에 실제로 그린 장치가 나옵니다.
- **화질:** `--res 480p`(무대의 4/9, 16:9면 854×480) · `720p`(2/3) · `1080p`(기본, 무대 크기 그대로) · `4k`(두 배). 화면 배치는 그대로 두고 그리는 픽셀 수만 바꾸므로
  글자와 도형은 어느 해상도에서나 선명합니다. 4K는 HEVC, 나머지는 H.264로 압축합니다.
  압축 정도는 `--quality`: `high`(기본) · `max`(더 좋음, 파일이 큼) · `ultra`(무손실 압축). `ultra`는 프레임을 JPEG 100으로 찍어
  크기 조정·색 줄이기 없이 H.264 YUV 4:4:4 무손실 압축으로 담습니다 — 압축에서는 잃는 것이 없고, RGB를 YUV로 바꿀 때의
  반올림과 JPEG 100의 아주 작은 손실만 남습니다. `--png`를 함께 주면 PNG로 찍습니다(찍는 데 시간이 더 걸림).
  대신 파일이 아주 크고(1080p 60fps에서 초당 수십 Mbps) 더 느리며, 4:4:4 H.264(High 4:4:4)를 재생하지 못하는
  플레이어(QuickTime 등)도 있습니다. 소리는 `high`·`max`와 같습니다.
- **시간:** 영상 길이보다 오래 걸립니다(긴 영상은 몇 시간). 먼저 `--to 40`으로 앞 40초를 만들어 속도를 보고, 필요하면
  `--fast`(한 번만 찍기 — 장면이 크게 바뀌는 순간 한 프레임이 늦게 찍힐 수 있음)나 `--jobs`로 줄입니다.
- **진행:** 한 줄이 계속 갱신됩니다 — `진행 12.3% · 남은 약 1:02:10 · … · 초당 8.94장`. Ctrl+C로 멈추면 조각마다 찍던 프레임까지
  마무리하고, 처음부터 끊김 없이 이어진 부분(끝난 조각들 + 그 바로 뒤 조각의 찍은 데까지)을 `movie_…_partial.mp4`로 저장합니다
  (한 번 더 누르면 저장하지 않고 바로 끝냄). 여러 조각을 동시에 만들므로 그보다 뒤에서 만들던 조각은 들어가지 않습니다. 같은 명령으로
  다시 실행하면 끝난 부분부터 이어서 만들고, 그사이 프로젝트를 고쳤으면 처음부터 다시 만듭니다(그사이 `--screenshot`으로 만든
  `screenshots/`는 고친 것으로 치지 않음). 이어 하지 않고 처음부터 만들려면 `--fresh`를 붙입니다(그 명령으로 만들다 남은 조각을 버림).
- **자막과 소리:** 자막은 기본으로 들어갑니다(`--no-captions`로 뺌). 소리는 만든 구간의 내레이션에, 소리를 켠 영상 클립(`audio: true`)의
  소리를 플레이어와 똑같이(위치·볼륨 변화·음량 맞춤, 항상 1배속)섞습니다. 내레이션이 임시 무음인 구간은 클립 소리만 들어갑니다.
  플레이어에서 배속으로 보던 중이어도 영상 파일의 내레이션·클립 소리는 늘 1배속입니다.
- **스크린샷:** `--screenshot`이면 MP4 대신 한 구간을 이미지 한 장에 모은 콘택트 시트를 만듭니다 — 아래 「스크린샷으로 훑어보기」.
- **글꼴 검사:** 렌더하면서 화면의 글자(5초마다)와 캔버스에 그린 모든 글자가 설치된 OFL 글꼴로 그려졌는지 확인하고,
  시스템 글꼴이 섞이면 경고합니다(`--no-font-check`로 끔).
- **영상 클립이 있는 영상:** 영상이 실제로 놓는 클립만 확인합니다(media-src.js에 적어만 둔 클립은 상관없음). 먼저 렌더용 프레임을 잘라 둡니다 — `node <스킬>/scripts/stills.mjs . --out media/render-stills --fps 60 --scale 1`
  (4K면 `--scale 2`, 720p면 `--scale 0.6667`, 480p면 `--scale 0.4444`). render.py는 그리기 전에 잘라 둔 프레임이 이번 해상도·fps에
  맞는지(가로 크기·장 수) 확인하고, 없거나 작거나(늘려 그리면 클립이 흐려짐) 장 수가 다르면 다시 자르는 명령을 알려 주고 멈춥니다. 그 명령을
  실행하면 stills.mjs가 맞는 것은 그대로 두고 맞지 않는 것만 다시 자릅니다(더 크게 잘린 것은 그대로 씀). 클립의 소리는 원본(`media/master`)에서 가져와 섞습니다.

### 스크린샷으로 훑어보기 (`--screenshot`)

MP4 대신 **콘택트 시트**를 만듭니다. 정해진 간격의 프레임을 480p로 찍어 이미지 한 장에 격자로 모은 것으로, 영상을 틀지 않고 한 구간의 흐름을
한눈에 보고, 칸 아래 적힌 `프레임 번호 · 시각 · cue`로 고칠 곳을 정확히 짚을 수 있습니다. 에이전트와 함께 리뷰할 때 시트를 보여 주면
에이전트가 그 이미지를 열어 같은 장면을 보며 이야기합니다.

```bash
python3 render.py --screenshot --from 8 --to 15 --gapframe 5    # 8–15초, 5프레임마다 (장면 전환·깜빡임)
python3 render.py --screenshot --from 40 --to 55 --gapframe 15  # 한 장면의 흐름
python3 render.py --screenshot --gapframe 300 --jobs 3          # 5초마다 — 영상 전체 훑어보기
python3 render.py --screenshot --at 12.5 --res 1080p            # 그 순간만, 무대 크기 그대로 (작은 글씨·세부)
python3 render.py --screenshot --at 12.5 --crop 1200,600,640,360 --res 4k   # 무대 일부를 두 배로
python3 render.py --screenshot --at 66.3 --via 74.3             # 74.3초에서 건너와 찍은 것과 비교 (다른 픽셀 표시)
python3 render.py --screenshot --art whale --viewbox "-200 -130 400 260" --at 0,0.6,1.2   # 그림 모듈 하나만
```

에이전트도 화면을 볼 때는 **언제나 이 시트만** 봅니다. 자기 스크린샷 코드를 쓰거나, MP4에서 프레임을 뽑거나, 다른 도구가 남긴 이미지를
열지 않습니다(스킬이 쓰이는 동안 훅이 이를 막고, `snapshot.mjs`·`preview_art.mjs`는 검사만 하고 그림을 만들지 않습니다).

- **`A` 키:** 영상을 보다가 `A`를 누르면 그 순간 앞뒤 1초를 10프레임마다 찍는 명령이 복사됩니다
  (`--screenshot --from 10.66 --to 12.66 --gapframe 10 --fast --jobs 1 (check it with render.py from the script-to-motion skill)`).
  에이전트에게는 그대로 붙여 넣으면 되고, 직접 실행할 때는 영상 폴더에서 `python3 render.py ` 뒤에 괄호 앞까지만 붙여 넣습니다.
- **출력:** 다 만들면 시트 이미지의 전체 경로만 한 줄에 하나씩 나옵니다(오류·경고는 stderr). 진행 상황을 보려면 `--progress`.
- **영상 파일:** 영상 폴더 대신 mp4·mov 등 영상 파일을 주면(`python3 render.py clip.mov --screenshot …`) 그 파일의 프레임으로
  같은 모양의 시트를 만듭니다 — 프레임 번호는 그 파일의 fps 기준, 시트는 파일 옆 `screenshots/`.
- **결과:** `screenshots/<영상 폴더>_<실행 시각>_<시작>-to-<끝>_every-<간격>-frames-at-<fps>fps_sheet-<번호>-of-<장 수>.jpg`
  (예: `내영상_20261109-101201_0m00.00s-to-0m10.00s_every-30-frames-at-60fps_sheet-1-of-1.jpg`). 가로 영상은 한 장에 4×6칸(854×480 칸), 세로 영상은 8×3칸, 넘치면 여러 장.
  이름에 실행 시각이 들어가 이전 시트를 덮어쓰지 않고, **`--clear`를 주지 않으면 아무것도 지우지 않습니다.** `--clear`를 주면
  새 시트를 다 만든 뒤 `screenshots/`를 비우고 이번 시트를 넣습니다.
- 자막은 기본으로 들어가고, 그림은 MP4와 같은 방식으로 찍으므로 영상과 같습니다. ffmpeg는 필요 없습니다(영상 파일의 시트만 ffmpeg로 프레임을 뽑습니다).

**자세한 사용법 — 처음 써 보기, 상황별 명령, 선택지 전체, 시트 읽는 법, 시간·크기 계산, 영상 클립, 이어 하기, 문제 해결, 자주 묻는 질문 —
은 [docs/screenshot.md](docs/screenshot.md)에 있습니다.**

### 화면 녹화로 만들기

1. 폴더 안의 `index.html`을 Chrome으로 엽니다(더블클릭). 검은 화면 가운데 로딩바가 차오르고, 다 차면 곧바로 재생됩니다.
   처음 재생부터 끊기지 않게 하려면 주소 뒤에 **`?warm`**을 붙여 엽니다(`index.html?warm`) — 로딩바의 뒤 절반 동안
   영상 전체를 한 번 미리 그려 둔 다음 재생합니다(시간이 조금 걸립니다).
2. `F` 키로 전체화면으로 바꾸고, 화면 녹화 프로그램(예: OBS)을 켠 뒤 `R`(처음부터)을 누릅니다.
3. 끝나면 녹화를 멈춥니다. 4K로 녹화해도 글자와 도형이 선명합니다.

- **소리 자동 재생이 막히면:** 브라우저 설정에 따라 클릭 없이는 소리 재생을 막을 때가 있습니다. 그때는 검은 화면 가운데
  재생 표시가 나오고, 클릭하거나 `Space`·`Enter`를 누르면 재생됩니다.
- **끊김 확인:** 녹화 전에 주소 뒤에 **`?watch`**를 붙여 한 번 돌려 보면(예열한 뒤 재생), 프레임이 빠지는 곳마다 그 자리에서
  멈추고 화면 전체가 1초 동안 빨갛게 됩니다(시각과 길이가 표시되고 콘솔에도 남습니다). 녹화할 때는 쓰지 마세요.
- **프레임 번호:** 주소 뒤에 `?fc`를 붙이면 왼쪽 아래에 지금 프레임 번호(60fps 기준, `?fc=30`이면 30fps)가 작게 나옵니다.
  녹화에 찍히므로 확인할 때만 쓰세요.

- **소리:** 시스템 소리를 같이 녹음하거나, 화면만 녹화한 뒤 편집 프로그램에서 `audio/narration.wav`를 깔면 됩니다.
  음성의 0초는 영상이 처음부터 움직이기 시작한 순간(`R`을 누른 순간)입니다.
- **자막:** 처음부터 켜져 있고(한 줄씩, 1080p 기준 60px), 재생 중 `C`로 끄고 켭니다(브라우저가 기억). 켠 채로 녹화하면 자막이 영상에 들어갑니다.
- **영상 속 소리:** 녹화 화면이나 생성 영상의 소리가 함께 나오는 영상은 `narration.wav`만으로는 그 소리가 빠지니,
  시스템 소리를 같이 녹음하세요.
- **세로·정사각 영상:** 가로 모니터에서 재생하면 양옆이 검게 나옵니다. 녹화 프로그램에서 영상 부분만 잘라 녹화하거나
  (OBS의 자르기 필터, 캔버스를 1080×1920 등 영상 크기로), 녹화 후 편집에서 잘라 주세요.

주소 뒤 옵션: `?warm` 예열하고 재생 · `?watch` 예열하고 끊김 감시 재생 · `?t=12.5` 그 시각부터 · `?fc` 프레임 번호

재생 중 단축키: Space 재생/정지 · ←/→ 0.5초 이동(Shift 5초) · Shift+> / Shift+< 배속(검수용, 3배속까지) · F 전체화면 · C 자막 · S 위치 복사 · A 스크린샷 명령 복사(에이전트에게 붙여 넣을 안내 포함) · D 디버그(초 단위 시각, Shift를 누른 채 마우스를 좌우로 움직이면 미세 이동) · R 처음부터(1배속으로 돌아감)

배속은 만드는 중에 빨리 넘겨 보기 위한 검수용입니다. 녹음되는 음성과 `render.py`로 만든 MP4의 소리는 언제나 1배속이고,
녹화를 시작할 때 누르는 `R`은 배속을 1배로 되돌립니다.

## 자주 묻는 질문

**mp4 파일로 바로 받을 수 있나요?**
네. `python3 render.py <프로젝트 폴더>`(폴더 안에서는 인자 없이)를 실행하면 `movie_<날짜-시각>_<해상도>.mp4`가 만들어집니다(1080p, `--res 480p`·`720p` 또는 `--res 4k`). 프레임 단위로
찍어서 끊김이 없습니다. 위의 「MP4로 굽기」를 보세요. 브라우저 재생을 화면 녹화해도 됩니다.

**목소리 없이도 만들 수 있나요?**
네. Fish Audio API 키와 음성 ID를 주지 않으면 내레이션 없이 화면의 글자와 움직임으로 전하는 영상으로 만듭니다.
나중에 키와 ID를 주면 그때 목소리를 입힐 수 있습니다.

**비용이 드나요?**
스킬 자체는 무료(MIT)입니다. 목소리를 만들 때 Fish Audio 사용 요금이 듭니다.

**글꼴은 마음대로 고를 수 있나요?**
영상에 상업적으로 써도 되는 **SIL 오픈 폰트 라이선스(OFL 1.1)** 글꼴 안에서 고릅니다. Google Fonts에 있는 OFL 글꼴이면
이름만 말해도 됩니다. 다른 라이선스의 글꼴을 요청하면 비슷한 OFL 글꼴을 제안합니다.

**같은 내용으로 가로·세로 둘 다 필요해요.**
"쇼츠 버전도 만들어줘"라고 하면 됩니다. 대본과 목소리는 그대로 쓰고, 화면은 세로에 맞게 새로 배치합니다.

**그림·아이콘·음악은 어디서 가져오나요?**
가져오지 않습니다. 화면의 그림, 캐릭터, 아이콘, 지도, 그래프, 3D 모델, 효과와 글은 모두 그 영상을 위해 새로 만듭니다.
효과를 만드는 기술(알고리즘, 셰이더 등)은 cokacmotion 기법 모음에서 배워 오지만, 그 기술로 무엇을 그릴지는 영상마다 새로 정합니다.
인터넷의 사진·아이콘·음악이나 다른 작품의 캐릭터·로고는 쓰지 않습니다. 직접 건네주신 파일(로고, 제품 사진 등)만 그대로 씁니다.

**인터넷이 꼭 필요한가요?**
처음 한 번은 글꼴과 애니메이션 라이브러리를 공식 배포처에서 내려받고, cokacmotion 기법 모음(약 70MB)도 받아 둡니다.
`render.py`는 처음 실행할 때 Playwright와 Chromium을 자기 가상환경에 한 번 받습니다.
기법 모음은 하루에 한 번까지 새 버전을 확인하고, 인터넷이 없으면 받아 둔 것을 씁니다. 완성된 영상 폴더는 인터넷 없이 재생됩니다.

## 설치

SKILL.md 형식의 스킬을 지원하는 에이전트에서 쓸 수 있습니다. 이 폴더를 에이전트가 스킬을 읽는 위치에 두세요.
예를 들어 Claude Code라면 `~/.claude/skills/script-to-motion`입니다.

> 이 스킬은 **macOS**와 **Linux**를 기준으로 만들었습니다.

```bash
git clone https://github.com/kstost/script-to-motion.git <스킬 폴더>/script-to-motion
cd <스킬 폴더>/script-to-motion/scripts && npm install
```

준비물

- **Node.js**와 **Chrome**(재생·녹화용). ffmpeg가 있으면 mp3도 만듭니다.
- **(MP4로 구울 때) Python 3과 ffmpeg** — 맥은 `brew install ffmpeg`. 나머지(Playwright, Chromium)는 `render.py`가 처음 실행할 때 알아서 준비합니다.
- **(내레이션을 원할 때) Fish Audio API 키와 음성 ID** — 요청할 때 함께 주세요. 방법은 [내레이션](#내레이션은-fish-audio로)에 있습니다.
- **인터넷(처음 한 번)** — 글꼴, 애니메이션 라이브러리, cokacmotion 기법 모음을 내려받습니다. 이후엔 캐시를 씁니다.
  기법 모음은 git이 있으면 git으로, 없으면 GitHub 압축 파일로 받습니다. 따로 설치할 필요는 없습니다.

**화면 보기 가드** — 에이전트는 영상 화면을 `render.py --screenshot` 시트로만 봅니다. 이를 지키는 가드(`scripts/hooks/look_guard.py`)가
스킬을 쓰는 동안 켜지고, 새 영상 프로젝트를 만들 때 작업 폴더의 `.claude/settings.local.json`(개인 설정, 커밋되지 않음)에도 들어가
보조 에이전트까지 지킵니다. 직접 넣기: `node <스킬 폴더>/scripts/hooks/install_guard.mjs` · 빼기: 같은 명령에 `--remove`.

에이전트가 따르는 작업 순서와 규칙은 [SKILL.md](SKILL.md), 세부 문서는 [references/](references/)에 있습니다.
