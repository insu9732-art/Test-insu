## 1. Project wiring

```
index.html        #stage (data-width/height) → persistent layers + <section class="scene" id="sNN">
css/player.css    runtime: Pretendard @font-face, stage scaling, loading screen, captions, debug bar
css/style.css     YOUR art direction
js/cues.js        generated by tts.mjs — window.VIDEO_DATA (cue timings). Never edit by hand.
js/sync.js        generated by sync.mjs — window.SYNC (the phrase times you set in script.json "at"). Never edit by hand.
js/player.js      runtime clock + helpers. Don't edit.
js/scenes.js      YOUR timeline: Video.define(ctx => { ... })
js/fxkit.js       optional effects kit (FXKit.install(ctx)) + css/fxkit.css — references/fx-kit.md

js/art/core.js    helpers for illustration modules js/art/<group>.js — references/art-library.md

vendor/gsap/      (downloaded by new_project.mjs / install_vendor.mjs from npm gsap@3.15.0, never edited)
                  gsap + SplitText, CustomEase, CustomBounce, CustomWiggle, DrawSVG, MorphSVG,
                  MotionPath, Text, ScrambleText (all registered by the player; ScrambleText uses Math.random — not
                  seek-safe, use FXKit kick() instead, references/fx-kit.md)
fonts/            PretendardVariable.woff2 (weights 45–920, Hangul + Latin) · d2coding/ (monospace, Hangul) ·
                  noto-sans-kr/ (captions) — core catalogue fonts, SIL OFL 1.1 only, downloaded from their official
                  sources by new_project.mjs (the skill ships no font files), sha256-verified, with licence files
css/fonts.css     (only when extras are installed) @font-face written by add_font.mjs from the skill's catalogue
                  (assets/fonts/catalog.json). No other font may be named anywhere (SKILL.md → Fonts)
```

Everything loads with plain `<script>` tags, so `index.html` works from `file://` (double-click).
Don't add `fetch()`, ES modules or CDN links — they break offline/file:// playback.

The stage is designed at a fixed logical size (1920×1080 for 16:9) and scaled to the window. Write all
sizes in stage pixels. Vector content (text, CSS, SVG) stays sharp at any output size, including 4K
fullscreen; raster images need 2× resolution to stay sharp there.

Boot order: fonts ready + audio ready → your `define` callback runs → first frame renders → start
screen. Because fonts are loaded before your code runs, SplitText and measurements are safe inside it.

## 2. `Video.define` context

```js
Video.define(({ tl, cue, cues, scene, onFrame, busy, rand, fitCanvas, stage, W, H, gsap, data }) => { ... });
```

| name | what it is |
|---|---|
| `tl` | the paused GSAP master timeline. Every tween goes on it. |
| `cue(id)` | `{ id, text, say, start, end, duration, measured, at(f), about(phrase, offset=0), when(phrase, offset=0) }`. Throws on unknown id. |
| `cue(id).about('구절')` | roughly when the phrase is spoken: its character position in the cue's text. For a moment that only follows the line (a scene change, a camera move, a panel entering while the line runs). No time to set, never warns. |
| `cue(id).at(f)` | time at fraction `f` (0–1) of the cue's spoken duration. |
| `cue(id).when('구절')` | the moment the phrase is spoken: **the time you set** for it — read off the take with `wave.mjs --cue`, written in script.json `at`, turned into `js/sync.js` by `sync.mjs` (references/sound.md §2; `cue(id).measured` is true while js/sync.js belongs to this take). Use it **only** where the picture must land on the spoken word (a number as it is said, a highlight on the word, an item as it is named) — everything else is `about()`, a cue label or `at(f)`. Any phrase without a set time (and every phrase until then, or after a re-take without a new `at`) is estimated by character position, accurate to a few hundred ms — the player warns once for a recorded cue. No code finds words or pauses in a take. |
| `cues` | all cues in order (same objects). |
| `scene(target, from, to)` | show `target` only in [from, to). Sets `visibility` only — opacity stays yours, so a scene's own fades never fight it and a backward seek can't leave a scene hidden. `to = null` → stays until the end. |
| `onFrame(fn)` | `fn(t, redraw)` runs every frame and on every seek. For canvas, counters with formatting, procedural motion. Must be a pure function of `t` (plus state tweened on `tl`). `redraw` is true once after the window was resized or went fullscreen (the `fitCanvas` canvases were re-sized, which blanks them): code that skips drawing while its inputs haven't changed must draw then. |
| `busy(fn)` | `fn()` → true while something still draws the current time asynchronously (e.g. an embedded demo that renders in a worker or over several frames). Only a frame-by-frame render (`?render`) reads it, through `Video.renderBusy()`: it waits, seeks to the same t again, then captures. Most videos never need it. |
| `rand(seed)` | deterministic PRNG (returns `() => 0..1`). |
| `fitCanvas(canvas, w=W, h=H, max=3)` | sizes a `<canvas>` for the current output resolution and returns a 2D context already scaled to stage pixels. Re-fits on resize and fullscreen (that blanks it; the frame drawn right after passes `redraw = true` to `onFrame`). `max` caps the pixel ratio: a heavy full-frame canvas (hundreds of sprites) at `max = 2` keeps playback smooth on high-density screens. |
| `stage, W, H` | the stage element and its logical size. |
| `data` | `window.VIDEO_DATA` (title, lang, duration, cues…). |

`define` may be `async` (e.g. to `await` something local), but nothing may depend on wall-clock time.

The video's length is `max(narration end + tail, tl.duration())`. An outro that runs past the
narration simply extends the video.

## 3. Positioning on the timeline

Each cue id is a timeline label, and so is `<id>_end`:

```js
tl.from('#s02 .title', { yPercent: 100, duration: 0.8, ease: 'expo.out' }, 'c04');         // cue start
tl.from('#s02 .sub',   { autoAlpha: 0, y: 24, duration: 0.6 },              'c04+=0.35');  // after start
tl.to('#s02',          { autoAlpha: 0, duration: 0.4 },                     'c05-=0.3');   // just before next cue
tl.to('#s02 .mark',    { scaleX: 1, duration: 0.5 },     cue('c04').when('핵심') - 0.1);   // hit a word
tl.from('#s02 .item',  { autoAlpha: 0, x: -40, stagger: 0.12 },             '<0.2');       // relative to previous tween
```

Anchor to cues, not to absolute seconds: when narration is regenerated (a script edit, a new take)
the cue times move and everything anchored to them moves too. A label that doesn't exist makes GSAP
silently append the tween at the end of the timeline — `check.mjs` catches that.

## 4. Rules (and why)

The player sets the timeline to `t` every frame. Anything that isn't a function of `t` breaks either
seeking (debug scrubbing, `?t=`) or repeatability between the user's takes when recording.

| Don't | Because | Do instead |
|---|---|---|
| `gsap.to/from/fromTo(...)` standalone | runs on wall-clock time, ignores pause/seek | `tl.to(...)`; `gsap.set` for initial state is fine |
| `repeat: -1` on `tl` | makes the master timeline infinitely long | finite `repeat`, CSS `@keyframes` loop, or `onFrame` |
| `Math.random()` | different every run and every seek | `const r = rand(42)` at build time |
| `Date`, `performance.now()`, `setTimeout`, `setInterval`, `requestAnimationFrame` | wall-clock | `onFrame(t => …)` |
| CSS `transition:` | wall-clock | tween the property on `tl` |
| toggling classes / `display:none` during playback | not seekable; `display:none` restarts CSS animations | `scene()` / `autoAlpha` on `tl` |
| `tl.call()`, `onComplete`, `onStart` | skipped or doubled when seeking | tween properties; derive in `onFrame` |
| `will-change` | layer can stay low-res when the stage scales up (fullscreen/4K) | leave it off; GSAP handles layers |
| `fetch`, modules, CDN URLs, remote fonts/images | break `file://` and offline playback | inline SVG, local files |
| setting a playback rate in your code: `audio.playbackRate`, `video.playbackRate`, `defaultPlaybackRate`, an audio node's `playbackRate` | the narration (the TTS takes) and every clip with sound always play at 1× — the user's absolute rule; only the player's review keys change the speed, and R puts it back to 1× | leave the rate alone; a **silent** clip may get its own speed with `M.clip(…, { rate })` (footage.md); `check.mjs` errors on any playback rate in project code |
| something that finishes drawing **after** a seek: an `<img>` whose `src` changes with t (a frame sequence), `new Image()`, an `<iframe>`, a `Worker`, `createImageBitmap` | in playback it catches up a frame later, unnoticed; a frame-by-frame render (`render.py`) captures the moment right after the seek — half-loaded, or the previous picture | load what is set once inside the async `define` (`await img.decode()`); for what changes with t register `busy(() => !img.complete)` (any test that is true while it still draws) — the render waits, seeks again, then captures. `js/media.js` already does this for footage frames |
| TSL `time` / `deltaTime` / `frameId` in a shader (FX build) | runs on `performance.now()`: keeps moving while paused, differs per seek | `fx.uTime` (= t, set by `fx.render(t)`) — shader-fx.md §3 |
| text with no installed font: `ctx.fillText` before setting `ctx.font` (default `10px sans-serif`), a generic-only stack (`font-family: sans-serif`), a `<button>`/`<input>` outside the template's inherit rule, SVG text in an `<img>` | the browser draws it with a system font — different per machine, not OFL | `ctx.font = "700 48px 'Pretendard', sans-serif"` before drawing; an installed family first in every stack; inline SVG; `check.mjs` + `check_fonts.mjs` |
| a system font in any stack (`system-ui`, Menlo, SF Mono, Arial…) or glyphs no bundled font covers (emoji) | differs per machine and may not be licensed for a published video; the recording won't match the verification | bundled OFL fonts only; SVG for icons; `check_fonts.mjs` |
| `fromTo(…, { immediateRender: false })` on an element that is already visible | before the tween starts, the element shows its **CSS default** (a full bar, a visible label), then snaps to the `from` state | `gsap.set(el, startState)` at build time, then `tl.to` / `fromTo` |
| a start position in a stylesheet (`transform: translateX(-100%)`) on an element you then tween with `xPercent`/`x` | GSAP parses the CSS matrix into `x` **pixels** and adds your `xPercent` on top, so the element moves twice as far and ends where it should be hidden (covering the stage after a wipe) | no `transform` in CSS for GSAP-driven elements; `gsap.set(el, { xPercent: -100 })` at build time |
| `text-shadow` (glow or soft shadow) on text inside a clipping box: SplitText `mask: 'chars' / 'words' / 'lines'` (each piece gets an `overflow: clip` wrapper), rolling-digit / odometer columns (`overflow: hidden` + mask), or any ancestor with `overflow: hidden/clip`, `clip-path` or `mask-image` | `text-shadow` is **inherited**, so every clipped char/digit draws its own glow and its box cuts it off at the edges: **faint coloured rectangles behind each character** (the wider the blur, the more visible). Easy to cause by accident: a glow on a shared class (`.num`, `.headline`) reaches text you split later | `text-shadow: none` on the clipped text; glow with `filter: drop-shadow(…)` on the split element or an ancestor that is not itself inside the clip — the filter shadows the already-clipped glyph shapes. See §5 "Glows on clipped text" |
| a second scale tween with a different `transformOrigin` | changing the origin of an already-scaled element moves it: a one-frame jolt | `gsap.set(el, { transformOrigin })` once; keep it for every scale tween on that element |
| `scale` / `rotation` on an **SVG element** (`<g>`, `<path>`, `<circle>`) without a deliberate origin | GSAP's default origin for SVG is the top-left of the element's bounding box, not its anchor: a weight scaled ×1.25 slid ~4 px off the rope it hangs from | bake static scale into the markup (`<g transform="scale(1.25)">` around the shape, with the anchor at 0,0), or set `svgOrigin: 'x y'` (SVG user units) / `transformOrigin` once at build time |
| parts that belong together (a sun disc, its halo and its lens flare; a label and its leader line; a weight and its rope) each computing their own position | they agree at rest and drift apart as soon as a camera or parent moves (the sun's glow separated from the sun while the camera sank) | one source of truth: put them in one group that moves, or derive every part's position from the same tweened value in one `onFrame` |
| `shake` / wiggle with absolute values (`x: 10`) on an element whose `x`/`y` is also tweened (a camera, a world, a scrolling strip) | the shake overwrites the position: the frame jumps to another place (the dive's landing jumped back 9,000 m for 0.3 s) | shake on an independent channel — FXKit `shake()` (a closed-form offset on the CSS `translate` property) — or shake a wrapper that nothing else moves |
| relative tweens (`x: '+=10'`) or `to` tweens on an element another tween keeps moving | a relative/`to` tween reads its start when first rendered; which moment that is depends on how the playhead got there, so after a seek the element sits a few px off (`snapshot.mjs --seekcheck` reports it) | explicit `fromTo` values, an independent channel (`translate`/`scale`/`rotate` CSS properties, a proxy object read in `onFrame`), or a wrapper element |
| `tl.to(x, {autoAlpha:1, duration:0.01})` then `tl.from(x, {…, immediateRender:false})` at the same time | the `from` reads its end value before the first tween has rendered, so it can end invisible | one explicit `fromTo(x, {autoAlpha:0,…}, {autoAlpha:1,…})`, e.g. an `inn()` helper |
| phrase-anchored tweens on one element inside the same cue | a "dim" at `cue+0.5` can land **after** a highlight at `when('first words')` and undo it | compute the times and check their order, or make the first state part of the entrance |

CSS `@keyframes` animations on elements inside the stage are fine (ambient loops, shimmer): the player
pauses them and sets their `currentTime = t`. They must exist from page load (declared in CSS on
elements that exist in `index.html`) so their clock starts at t=0.

### Performance (frame drops are a bug the user sees)
- Many moving things on a canvas (falling notes, coins, cards): draw each picture **once** into a small sprite canvas
  and place it with `drawImage` every frame — no path drawing, gradients, `ctx.filter` or `shadowBlur` per frame
  (pre-blur copies for out-of-focus layers). Cap the canvas with `fitCanvas(c, W, H, 2)`.
- Skip work outside a scene's window (`if (t < a || t > b) return;`) and cache DOM writes (compare with the last value).
  A canvas that skips drawing when nothing changed must still draw when `onFrame` passes `redraw = true` (after a
  resize or F the canvas is blank): `onFrame((t, redraw) => { if (!redraw && key === lastKey) return; … })`.

## 5. Recipes

All tested with the player. Adapt, don't paste blindly.

### Scene visibility with overlapping transitions
```js
const a = cue('c01'), b = cue('c02'), c = cue('c03');
scene('#s01', 0, b.start + 0.4);          // stays a bit into c02 so the exit can overlap the entrance
scene('#s02', b.start - 0.2, c.start + 0.4);
scene('#s03', c.start - 0.2, null);
tl.to('#s01 .content', { autoAlpha: 0, y: -40, duration: 0.45, ease: 'power2.in' }, 'c02-=0.2');
```

### Kinetic type with SplitText (Korean-safe)
```js
// words+chars keeps line breaks between words (word-break: keep-all); mask clips the rise
const t1 = SplitText.create('#s01 .headline', { type: 'words,chars', mask: 'chars' });
tl.from(t1.chars, { yPercent: 120, duration: 0.9, ease: 'expo.out', stagger: 0.028 }, 'c01+=0.05');
// by line (e.g. a 2-line statement) — lines are measured, so create it inside define (fonts are ready)
const t2 = SplitText.create('#s02 .statement', { type: 'lines', mask: 'lines' });
tl.from(t2.lines, { yPercent: 105, duration: 1.0, ease: 'power4.out', stagger: 0.12 }, 'c02');
```
Keep animated chars under ~250 at once; for long text split by words or lines.
`mask` wraps every char/word/line in an `overflow: clip` box — no `text-shadow` on masked text (§4, next recipe).

### Glows on clipped text (masked SplitText, rolling digits)
A glow drawn by `text-shadow` is clipped per character by the mask/overflow box and shows as faint
rectangles behind every letter. Verified in Chromium: plain text + `text-shadow` is fine; the same text with
SplitText `mask: 'chars'` or in `overflow: hidden` digit columns shows a box per character; `text-shadow: none`
plus `filter: drop-shadow()` on the parent is clean in both cases.
```css
.headline { text-shadow: none; filter: drop-shadow(0 0 16px rgba(89, 243, 224, .8)); }  /* the split element itself or any ancestor outside the clip */
.odo { text-shadow: none; filter: drop-shadow(0 8px 18px rgba(0, 6, 18, .5)); }           /* rolling-digit wrapper */
```
- `text-shadow` is inherited: clear it on the clipped text even when the glow is set on a shared parent class.
- `drop-shadow` blur reads about 2–2.5× softer than the same `text-shadow` value: `drop-shadow(0 0 16px)` ≈ `text-shadow: 0 0 40px`.
- The element carrying the filter must not itself be inside a clipping box, or the filtered glow is cut there instead.
- Alternative when the glow must stay a text-shadow: don't mask that text (animate opacity/`y` without `mask`).

### Count-up numbers (formatted)
```js
const n = { v: 0 };
tl.to(n, { v: 1280000, duration: 1.6, ease: 'power3.out' }, 'c05+=0.2');
const out = document.querySelector('#s05 .num');
onFrame(() => { out.textContent = Math.round(n.v).toLocaleString('ko-KR'); });
```
Give the number a fixed width (`font-variant-numeric: tabular-nums; min-width: …`) so layout
doesn't jitter while counting. If you make the digits roll (each digit a column in an `overflow: hidden`
box), the number's glow must move off the digits to a `filter: drop-shadow()` on the wrapper ("Glows on clipped text").

### Canvas particles (closed-form, seekable)
```html
<canvas id="field"></canvas>   <!-- inside a scene or as a persistent layer; position:absolute; inset:0 -->
```
```js
const ctx = fitCanvas(document.getElementById('field'));
const r = rand(7);
const pts = Array.from({ length: 160 }, () => ({ x: r() * W, y: r() * H, v: 10 + r() * 40, a: r() * 6.28 }));
onFrame((t) => {
  ctx.clearRect(0, 0, W, H);
  ctx.fillStyle = 'rgba(255,255,255,0.55)';
  for (const p of pts) {
    const x = (p.x + Math.cos(p.a) * p.v * t + W) % W;   // position from t, never accumulated
    const y = (p.y + Math.sin(p.a) * p.v * t + H) % H;
    ctx.fillRect(x, y, 2, 2);
  }
});
```

### Sub-timelines for complex beats
```js
function beat(pos, build) {
  const sub = gsap.timeline();   // not paused — tl.add() takes it over immediately
  build(sub);
  tl.add(sub, pos);
}
beat('c08', (b) => {
  b.from('#s08 .card', { y: 80, autoAlpha: 0, stagger: 0.1, duration: 0.7, ease: 'expo.out' })
   .to('#s08 .card', { rotationY: 180, duration: 0.8, ease: 'power3.inOut' }, '+=0.8');
});
```

## 6. Player controls (for the hand-off message)

- Loading screen — opening the page shows a black screen with one thin loading bar in the middle (no buttons); when the
  video is built it fades and **plays at once** (from the saved position when resuming). `Video.progress(p)` (0..1) lets a
  long build in scenes.js move the bar (the player itself takes it to 0.2 before the build and 0.97 after). If the
  browser refuses to start the sound without a click, the black screen comes back with a play mark (click / Space /
  Enter). `?warm` warms up first (the bar's second half), `?watch` warms up and turns the drop watch on. Automated
  browsers and `?render` never start playback. Fullscreen is the F key; when recording, R plays from the start at 1×.
- **Warm-up.** The first time a scene is shown the browser lays it out, rasterises it, decodes its images and compiles
  its shaders; on a slow computer that drops frames on the first viewing only. The warm-up does it before playing:
  decodes the stage's images, runs the video's own hooks (`window.__warmHooks`: `async (progress) => …`, e.g. demos that
  set up WebGL once), then paints the whole timeline once, a frame per second of video (`window.__warming` is true
  meanwhile, so heavy layers may skip work), on the second half of the loading bar. The playhead goes back to where
  it started; the picture is never affected. Off in renders, headless checks and with `?nowarm`.
- **Drop watch** (`?watch`). While playing, each display interval is compared with the display's steady interval (the lower
  quartile of the last two seconds); one longer than 1.6× that + 2 ms is a dropped frame: playback stops on that
  frame, the whole window turns red for a second (label: drop n · time · ms), then it simply goes on (no rewind).
  Nothing is judged right after play, a seek or while the tab is hidden. Every drop is kept in `window.__drops`
  (`{ t, ms, frames }`) and logged to the console — use it to find stutter before recording, not while recording.
- While playing the cursor hides (reappears on mouse move) and no UI is visible — safe to record.
- Keys: Space play/pause · ←/→ ±0.5 s (Shift ±5 s) · **Shift+> / Shift+<** review speed 0.25–3× (0.25 steps up to
  2×, then 2.5× and 3×; YouTube's shortcuts; narration pitch preserved; footage clips follow it; a small "1.5x" toast
  shows for 0.9 s) · `,` `.` ±1 frame when paused · Home/0 start · **R** restart+play at 1× ·
  F fullscreen · C captions (cue text; the choice is remembered in this browser) · **S copy position** ·
  **A copy the contact-sheet command** for this moment (`--screenshot --from t−1 --to t+1 --gapframe 10 --fast --jobs 1
  (check it with render.py from the script-to-motion skill)` — the note is for an agent it is pasted to; in a terminal,
  paste up to the parenthesis after `python3 render.py ` in the project folder — references/render.md) · D debug bar
  (one row: the time in seconds as --from/--to take it, the timeline with the cue and line written inside, scrubber).
  Letter keys work by physical key, so they also work with the Korean input method on.
- **Speed is for review only.** Shift+> / Shift+< let the user skim while producing; nothing made for the audience is
  ever at another speed. R — the key that starts a screen recording — always goes back to 1× (with the "1x" toast if it
  was off), and `render.py` films frame by frame and muxes the narration at 1×, so recordings and rendered MP4s are
  always 1×. Narration is never generated at another speed either.
- **S — review notes.** S copies `0:55.12 / 9:13.99 [op05] 대사…` (time, cue id, line) to the clipboard. The user
  pastes it above a note ("[op05] 여기 화면이 …"), so every piece of feedback arrives with its exact moment — answer
  with the same time and cue id.
- **Resume.** Reloading the page goes back to where it was — the way to review a change: edit, reload, and after the
  loading bar it plays on from the same moment. `?t=` overrides it; automated browsers never use it.
- **Debug scrubbing.** With the debug bar on (D), moving the mouse left/right **while holding Shift** scrubs without
  clicking (without Shift the mouse moves freely and the playhead stays): near the
  bottom edge 1 px = 1/3000 s (frame-exact), near the top 1 px = 2 % of the video, exponential in between.
- URL params: `?t=12.5` open at a time · `?debug` · `?captions` · `?stills` (footage as pre-cut frames, what the
  review tools use) · `?warm` · `?watch` · `?nowarm` (the warm-up does nothing) · `?fc` frame counter, bottom left of the window
  (60 fps; `?fc=30` counts at 30 — off by default because a screen recording would film it) · `?render` (below).
- **Frame-by-frame render (`?render`).** For a tool that films the video frame by frame in a headless browser
  (seek → wait → capture; nothing plays in real time, so nothing can drop): the loading screen, debug bar, speed toast,
  frame counter, warm-up and drop watch are off (`body.vp-render`), every `fitCanvas` canvas is drawn at the full
  device pixel ratio (a 4K capture at ratio 2 stays sharp; the `max` cap only spares live playback),
  `Video.renderReady` turns true once the scenes are built (with `body.vp-ready`), and `Video.renderBusy()` is true
  while anything registered with `busy(fn)` is still drawing (footage frames register themselves). `render.py` in
  the project folder is that tool (README 「MP4로 굽기」); it also works with projects made before this contract, by
  hiding the loading screen itself and treating the page as never busy.
- **Captions are always one line.** The player cuts each cue into segments that fit (measured with the
  real caption font), breaking after `, . ? ! …` first and never inside a word, and shows each segment for
  its share of the spoken cue. Defaults (the user's choice): **Noto Sans KR Bold**, 60px (readable on a phone too; a longer
  cue simply becomes more segments), on by default (C toggles and is remembered), placed as low
  as possible — 20px above the bottom edge. The font is installed into every project by new_project.mjs (`fonts/noto-sans-kr/`, SIL OFL 1.1,
  unicode-range subsets) and the player preloads the glyphs of every caption before measuring.
  CSS variables on `#stage` adjust them: `--caption-bottom` (default `20px`), `--caption-max` (default
  `80%`; px or %), `--caption-font` (default `'Noto Sans KR', Pretendard, sans-serif`). If your own UI
  sits along the bottom (e.g. a HUD in the corners), keep the captions' width between it
  (`--caption-max: 1080px`) rather than raising them. To choose the
  segments yourself, give the cue `captions: ["…", "…"]` in script.json (re-run tts.mjs). Look at them on render.py
  sheets (captions are on there) and check `snapshot.mjs --captions` for layout warnings.
- The last frame holds when the video ends; press R to replay.
